# Aman AI — دليل التشغيل والنشر بعد الربط الكامل

هذي نسخة محدّثة من المشروع بعد ربط الأجزاء الأربعة ببعض:
**التطبيق (Flutter)** ↔ **الباك-إند (FastAPI)** ↔ **الوكلاء (n8n، 8 وكلاء AI)** ↔ **قاعدة البيانات (PostgreSQL)**،
بالإضافة لداشبورد React للموظفين.

## البنية

```
├── app/                  تطبيق Flutter (Android + Web — بدون iOS، راجع IOS_PUBLISHING.md)
├── aman-backend/         باك-إند FastAPI (المصدر الوحيد للحقيقة لقاعدة البيانات)
├── dashboard/             داشبورد React للموظفين (شرطة/إسعاف/دفاع مدني)
├── n8n-workflows/         وركفلو الوكلاء الثمانية + دليل الربط (README_INTEGRATION.md)
└── docker-compose.yml     تشغيل محلي كامل (قاعدة بيانات + باك-إند + n8n) بأمر واحد
```

## ما الذي كان معطوبًا وما الذي أُصلح

| المشكلة | الحل |
|---|---|
| الباك-إند بدون أي `/api/auth/*` أو `/api/reports/*` بينما التطبيق والداشبورد يتوقعانها | أُضيفت كاملة بـ `app/auth.py` و `app/reports.py` |
| الوكلاء الثمانية يحللون البلاغ ثم **يرمون النتيجة** (ما فيه اتصال بالباك-إند إطلاقًا) | عقدة HTTP جديدة بنهاية الوركفلو + endpoint استقبال `/api/reports/{id}/classification` |
| `report_id` يتولّد مرتين بشكل مختلف (مرة بالباك-إند، ومرة بالوركفلو) | وُحِّد ليُستخدم رقم الباك-إند بكل مكان |
| أخطاء FastAPI بصيغة `{"detail": ...}` بينما العملاء يقرؤون `body['message']` | معالج أخطاء موحّد بـ `main.py` |
| `applicationId` أندرويد كان `com.example.aman_ai_app` (مرفوض بمتجر Google Play) | غُيّر لـ `com.amanai.app` + إعداد توقيع Release |
| `requirements.txt` ناقص `opencv-python`/`pillow` رغم استخدامهم بمعالجة الصور | أُضيفت |
| لا توجد سكيما SQL لقاعدة البيانات بالمشروع أصلًا | `aman-backend/app/schema.sql` — تُطبَّق تلقائيًا عند إقلاع الباك-إند |
| **تمويه الوجوه لم يعمل إطلاقًا منذ بداية المشروع** — `BLUR_STRENGTH = 30` (رقم زوجي) يُسقط `cv2.GaussianBlur` بصمت عبر try/except، فتحفظ كل صورة بدون تمويه رغم نجاح كشف الوجه | غُيّرت لـ `31` (فردي، كما يتطلب OpenCV) + سكربت `reprocess_old_images.py` لمعالجة الصور القديمة المتأثرة |
| `risk_score` يظهر دائمًا 0% بالداشبورد — الواجهات تضرب القيمة بـ100 (تتوقع كسر 0-1) بينما توجيه الوكيل ما يحدد نطاقًا واضحًا | وُحّد النطاق إلى عدد صحيح 0-100 بكل مكان (توجيه Agent3 + دالة تطبيع دفاعية بالباك-إند تقبل أي صيغة + إزالة الضرب الخاطئ من الداشبورد والتطبيق) |
| لا توجد وسيلة لعرض بيانات EXIF (GPS/تاريخ الالتقاط) أو تقييم صحة الصورة بالداشبورد رغم استخراجها | قسمان جديدان بـ`ReportDetail.tsx`: تفاصيل الصورة (مع مقارنة GPS بموقع البلاغ المُدخل) + تقييم صحة الصورة/احتمال التوليد بالذكاء الاصطناعي (Agent8 محسَّن) |

## التشغيل المحلي (للتجربة قبل النشر)

```bash
docker compose up --build
```

- الباك-إند: http://localhost:4000
- n8n: http://localhost:5678 (أول مرة: استورد ملفات `n8n-workflows/*.json`، فعّل الوركفلو، واربط بيانات اعتماد OpenAI — التفاصيل بـ `n8n-workflows/README_INTEGRATION.md`)
- الداشبورد: `cd dashboard && npm install && npm run dev` (أنشئ `.env.local` من `.env.example`)
- التطبيق: `cd app && flutter run --dart-define=API_BASE_URL=http://localhost:4000` (أو عدّل `ApiConfig.overrideBaseUrl`)

كود دخول موظف تجريبي (بعد أول تشغيل، من `schema.sql`): `ADMIN-0000` (مدير عام يشوف كل الجهات).
**غيّره فورًا قبل أي نشر حقيقي** عبر `UPDATE staff SET access_code = '...' WHERE access_code = 'ADMIN-0000';`

## النشر الفعلي — بالترتيب

### 1. قاعدة البيانات → Supabase
- تم تطبيق `aman-backend/app/schema.sql` على مشروع Supabase.
- من Supabase: `Project Settings → Database → Connection string` انسخ رابط Postgres وضعه كمتغير `DATABASE_URL` في استضافة الباك-إند.
- لا تضع كلمة المرور في GitHub أو داخل ملفات الواجهة.

### 2. الباك-إند → Render (أو Railway/Fly.io بنفس الفكرة)
- ارفع مجلد `aman-backend` كمستودع Git منفصل (فيه Dockerfile و`render.yaml` جاهزان).
- على Render: New → Blueprint → اختر المستودع، ثم أضف `DATABASE_URL` يدويًا من Supabase؛ ملف `render.yaml` لم يعد ينشئ قاعدة PostgreSQL ثانية.
- اضبط أيضًا: `ALLOWED_ORIGINS`, `N8N_WEBHOOK_URL`, `N8N_CALLBACK_SECRET`, `PUBLIC_BASE_URL`.

### 3. n8n → أي استضافة (n8n Cloud هو الأسهل، أو self-host)
راجع `n8n-workflows/README_INTEGRATION.md` بالتفصيل — يشمل ربط `AMAN_BACKEND_URL` و `N8N_CALLBACK_SECRET` رجوع بالاتجاه المعاكس.

### 4. الداشبورد → Vercel/Netlify (ثابت 100%، بناء بأمر واحد)
```bash
cd dashboard && npm run build   # ناتج build/ جاهز للرفع
```
اضبط `VITE_API_BASE` بمتغيرات بيئة منصة النشر لرابط الباك-إند من الخطوة 1.

### 5. التطبيق → المتاجر
- **أندرويد**: `app/android/KEYSTORE_INSTRUCTIONS.md` (خطوة بخطوة)
- **iOS**: `app/IOS_PUBLISHING.md` — **يتطلب جهاز Mac إجباريًا**، هذا قيد من Apple نفسها وليس قيدًا مني
- قبل البناء النهائي: `flutter build ... --dart-define=API_BASE_URL=https://your-backend.onrender.com`

## كشف الصور المولّدة بالذكاء الاصطناعي — كيف يشتغل وحدوده

Agent8 (تحليل الصورة) محسَّن الآن ليجمع إشارتين معًا:

1. **تحليل بصري بـ GPT-4o-mini** — يُطلب منه صراحة البحث عن آثار توليد شائعة
   (أصابع غير طبيعية، تماثل مبالغ فيه، نصوص خلفية مشوّهة، إضاءة غير متسقة، إلخ)
2. **غياب/وجود EXIF كاميرا حقيقية** (`has_camera_exif`) — إشارة سياقية إضافية وليست دليلًا وحده

النتيجة تُخزَّن بحقلين: `image_ai_generated_suspected` (true/false) و
`image_ai_generated_reason` (تفسير نصي)، وتظهر بالداشبورد بقسم مخصص
"تقييم صحة الصورة" جنب باقي تفاصيل البلاغ.

**⚠️ حدود حقيقية يجب معرفتها:**
- هذا **تقييم احتمالي بذكاء اصطناعي، مو أداة كشف موثوقة معتمَدة**. النماذج
  الحديثة (خصوصًا Midjourney v6+/Flux) تنتج صورًا يصعب تمييزها بصريًا حتى
  على العين المدربة، وGPT-4o-mini قد يُخدع بها أحيانًا.
- غياب EXIF وحده **ليس دليلًا** — كثير من تطبيقات المراسلة (واتساب، تيليجرام)
  تحذف EXIF تلقائيًا من صور حقيقية تمامًا عند إرسالها.
- لو تحتاجون دقة أعلى لقرارات حساسة، الخيار الأصح هو **خدمة كشف متخصصة**
  مثل Hive Moderation أو Sightengine أو "AI or Not" — تحتاج اشتراك API
  خاص بكم وربطها بعقدة HTTP إضافية بوركفلو Agent8 (نقطة الربط جاهزة، بس
  التسجيل بالخدمة والمفتاح خارج نطاق ما أقدر أسويه بدون حسابكم).
- عاملوا `image_ai_generated_suspected: true` كـ **إشارة تستدعي مراجعة
  بشرية إضافية**، مو رفض تلقائي للبلاغ.

## أشياء تستاهل انتباهك قبل الإطلاق الحقيقي (خارج نطاق الكود)

- **إرسال SMS/إيميل الحقيقي**: التحقق حاليًا "تجريبي" (يطبع الرمز بسجلات السيرفر فقط، لاحظ التعليق بـ `app/auth.py` دالة `_send_code`). اربطها بمزود حقيقي (Twilio/Resend) قبل الإطلاق.
- **سياسة الخصوصية**: `/privacy-policy` بالباك-إند يرجع JSON — Google Play وApple يطلبون **رابط صفحة ويب فعلية**، حوّلها لصفحة HTML منشورة بنطاق عام.
- **بيانات فرق الاستجابة** (`response_units`) وأكواد الموظفين الافتراضية بـ `schema.sql` بيانات تجريبية — استبدلها ببياناتك الحقيقية.
- **مفتاح OpenAI**: الوكلاء الثمانية يحتاجون بيانات اعتماد OpenAI حقيقية بعقد `lmChatOpenAi` بكل وركفلو — راجع تكلفة الاستخدام المتوقعة قبل الإطلاق العام.

## تحسينات أخرى

- **تجمّع اتصالات قاعدة البيانات** — كان كل طلب يفتح اتصالًا جديدة؛ خطة Render تسمح بـ ~20 اتصالًا فقط
- **إعادة محاولة n8n** — 3 محاولات بتراجع أسّي (2ث، 4ث) للأخطاء العابرة فقط
- **فحص إقلاع** — بوضع `ENVIRONMENT=production` يرفض الباك-إند الإقلاع لو الإعداد غير آمن
- **ترويسات أمان** — `nosniff` مهمة تحديدًا لأن `/media` يقدّم ملفات المستخدمين مباشرة
- **تحقق من الحالات** — `status` صار من قائمة معروفة بدل أي نص

## الجولة الثانية — النقاط المتبقية

| النقطة | الحالة | ماذا صار |
|---|---|---|
| أرقام بلاغات متسلسلة | ✅ | رمز عشوائي `AMN-K7M2QX9P` (٨٥٠ مليار احتمال) بدل `AMN-1001` |
| بلاغ يضيع من خط الوكلاء | ✅ | تتبّع بقاعدة البيانات + عامل إعادة محاولة + قائمة مراجعة بالداشبورد |
| رمز التحقق يُطبع بالسجلات | ✅ | مزوّد حقيقي (Resend / Twilio) — يحتاج مفتاحك فقط |
| حد المعدّل بذاكرة العملية | ✅ | Redis عند توفّره، مع رجوع تلقائي للذاكرة |
| أسماء ملفات عربية تضيع | ✅ | مدعومة، مع إزالة محارف الاتجاه المستخدمة لتزوير الامتدادات |
| لا اختبارات آلية | ✅ | ٤٠ اختبارًا يغطّي كل ضابط أمني (`pytest tests/`) |

### دورة حياة البلاغ الآن

```
البلاغ يُحفظ  →  pending
     ↓
٣ محاولات فورية (٢ث، ٤ث)  →  completed ✅
     ↓ فشلت
  failed + موعد إعادة محاولة
     ↓
عامل دوري كل ٦٠ث، تراجع ٢/٤/٨/١٦ دقيقة، حتى ٥ محاولات
     ↓ استنفدها
يظهر بـ /api/reports/needs-review مع شارة ⚠︎ بالداشبورد
```

يغطّي أيضًا البلاغ العالق بـ `processing` لأن الخدمة أُعيد نشرها في منتصف
الاستدعاء — مهمة الخلفية تموت مع العملية، والعامل الدوري يلتقطها بعد ١٠ دقائق.

**مهم بالداشبورد**: البلاغ غير المُصنَّف كان يبدو للموظف بلاغًا عاديًا بأولوية
منخفضة، بينما هو **غير مُقيَّم أصلًا**. الفرق حرج بقرار طوارئ، فصار له تحذير صريح.

## ما زال خارج نطاق الكود

هذه تحتاج حسابات أو قرارات منك، لا تعديلًا برمجيًا:

1. **مفتاح Resend أو Twilio** — الكود جاهز، اضبطي `NOTIFY_PROVIDER` والمفتاح
2. **Redis** — Render يوفّره بضغطة؛ بدونه يشتغل النظام لكن حد المعدّل أضعف
3. **صفحة سياسة خصوصية HTML** — المتاجر تطلب رابط صفحة، لا JSON
4. **بيانات فرق الاستجابة الحقيقية** — الموجود بيانات تجريبية لمسقط
5. **مراجعة تكلفة OpenAI** — ٨ وكلاء × كل بلاغ

## قبل النشر — إلزامي

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"   # سر n8n
python -c "import secrets; print(secrets.token_urlsafe(16))"   # كود موظف
```

بلوحة Render: `ENVIRONMENT=production`، `ALLOWED_ORIGINS`، `N8N_CALLBACK_SECRET`،
`PUBLIC_BASE_URL`، `NOTIFY_PROVIDER` + مفتاحه، و`REDIS_URL` إن توفّر.

الباك-إند **يرفض الإقلاع** لو نقص أي منها — عمدًا، حتى لا يمر إعداد ناقص بصمت.

# الجولة الثالثة — تحسينات جوهرية (26 أغسطس)

## ١. ربط البلاغات المكررة — الميزة المميّزة

**المشكلة**: حريق واحد بمنطقة مزدحمة = ٢٠ بلاغًا. النظام السابق يعاملها ٢٠ حادثًا:
٢٠ بطاقة بغرفة العمليات، ٢٠ استدعاءً لخط الوكلاء، واحتمال إرسال فرق متعددة
لنفس الموقع بينما مناطق أخرى تنتظر.

**الحل**: بلاغ من نفس النوع، ضمن ٥٠٠ متر، خلال ٢٠ دقيقة ← يُربط كتأكيد
للحادث القائم بدل أن يُعامل حادثًا جديدًا.

**ثلاث فوائد في آن**:

| | |
|---|---|
| غرفة العمليات | حادث واحد بدل ٢٠ بطاقة |
| التكلفة | ~٩٥٪ توفير بنداءات النماذج |
| المصداقية | ٢٠ مصدرًا مستقلًا = دليل قوة يصعب تزويره |

الفائدة الثالثة هي الأهم: **تحقق من صحة البلاغ بلا ذكاء اصطناعي إطلاقًا**.
بلاغ منفرد قد يكون كاذبًا؛ عشرة بلاغات من أجهزة مختلفة عن نفس النقطة خلال
دقائق يصعب تزويرها.

## ٢. الموقع الحقيقي بدل تخمين النموذج

`Agent 4` كان يستقبل إحداثيات ويُطلب منه تحديد الولاية والحي — والنماذج
اللغوية **لا تجري تحويلًا جغرافيًا عكسيًا**، هي تستدعي ما تتذكره فتصيب في
المشهور وتخترع في غيره.

استُبدل بـ **Nominatim** (OpenStreetMap): مجاني، بلا مفتاح، ويعطي الولاية
والمحافظة والحي فعليًا من قاعدة بيانات جغرافية. عند تعذّر الاتصال يرجع
`unavailable` — **لا يخمّن**، لأن غياب المعلومة أوضح من معلومة مخترعة.

## ٣. تحليل البيانات الوصفية للصور

النظام كان يخزّن وقت الالتقاط والإحداثيات **ويعرضها كأرقام خام** — والموظف
مطالَب أن يلاحظ بنفسه أن صورة «الحادث الآن» التُقطت قبل ثلاثة أيام. لن يفعل
تحت ضغط غرفة عمليات.

الآن المقارنة آلية والنتيجة تحذير صريح:

| الحالة | الإشارة |
|---|---|
| صورة قبل ٤ أيام | ⚠︎ قد تكون معاد استخدامها |
| موقع الصورة يبعد ١٧٩ كم | ⚠︎ تحقق مطلوب |
| أثر فوتوشوب بالبيانات | ⚠︎ مرّت ببرنامج تحرير |
| كل شيء متسق | ✓ درجة اتساق ١٠٠٪ |

⚠️ **مهم**: غياب البيانات الوصفية **ليس اتهامًا** — واتساب وأغلب التطبيقات
تحذفها. النبرة «يحتاج انتباه» لا «مزيّف»، ولا يُخفَّض التقييم بسببه.

## ٤. تمويه أقوى بكثير

**المشكلة**: النسخة السابقة استخدمت كاشف الوجه الأمامي وحده. وصور الحوادث
الحقيقية مليئة بما لا يكشفه: المارّة يلتفتون (وجه جانبي)، المصاب ملقى (وجه
منحنٍ)، والحادث المروري يُظهر **لوحة السيارة** التي تقود مباشرة لهوية المالك.

أي أن وعد الخصوصية كان يفشل **بالضبط في الحالات التي يهم فيها أكثر**.

**الآن**:
- أربعة كواشف وجه (أمامي ×٢ + جانبي بالاتجاهين)
- **كاشف أشخاص (HOG)** يتعرف على الجسم كاملًا ويموّه منطقة الرأس — يغطي
  الوجوه التي تفوت كواشف الوجه
- **كشف لوحات المركبات** وتمويهها
- بكسلة قبل التمويه (التمويه الجاوسي وحده يمكن عكسه جزئيًا)
- توسيع منطقة الوجه ٢٥٪ (الشعر والفك يكفيان للتعرف أحيانًا)
- موازنة إضاءة (صور الحوادث كثيرًا ما تكون ليلية)
- **فشل آمن**: تعذّر الكشف ← تمويه الصورة كاملة، لا تركها كما هي

## ما لم يُختبر بالكامل

- **Nominatim**: تحقق من منطق التحليل والذاكرة المؤقتة والفشل الآمن بمحاكاة،
  لكن النداء الحقيقي لم يُجرَّب (قيود شبكة بيئة التطوير). جرّبيه على جهازك.
- **دقة كشف الوجوه على صور حقيقية**: اختُبر على صور اصطناعية. الكواشف
  التقليدية أضعف من النماذج العصبية — **اختبري بصورة حقيقية فيها أشخاص**
  قبل الاعتماد عليه. لو الدقة غير كافية، الترقية لـ YuNet تتطلب تنزيل ملف
  نموذج (~٢٣٠ ك.ب) من opencv_zoo.
